Advanced TypeScript: The Type System Under the Hood

A deep dive into conditional types, distributive unions, inference, variance, mapped types and the techniques that let TypeScript model surprisingly complex APIs.

TypeScript is much more than JavaScript with annotations. Its structural type system has a surprisingly expressive type-level language. The key is to stop thinking of types as labels and start thinking of them as sets of possible values.

1. Types behave like sets

A union represents a value that belongs to one of several sets. An intersection represents a value satisfying multiple constraints.

type Role = "admin" | "editor";

type WithId = { id: string };
type WithName = { name: string };

type User = WithId & WithName;

This model explains why unions, intersections and never compose so powerfully.

2. Conditional types are type-level branching

type IsString<T> =
  T extends string ? true : false;

type A = IsString<"hello">; // true
type B = IsString<42>;      // false

The condition asks whether the supplied type is assignable to the constraint. This becomes the foundation for reusable type transformations.

3. infer extracts structure

infer introduces a type variable by matching part of a type's structure.

type ReturnTypeOf<T> =
  T extends (...args: any[]) => infer R ? R : never;

type Result =
  ReturnTypeOf<() => Promise<User>>;
// Promise<User>

Think of this as pattern matching over types. Many built-in utilities are variations on the same technique.

4. Distributive conditional types

A conditional type distributes over a union when the checked type is a naked type parameter.

type ToArray<T> =
  T extends unknown ? T[] : never;

type Result = ToArray<string | number>;
// string[] | number[]

It is effectively evaluated once for each union member. To prevent distribution, wrap the type parameter:

type ToArray<T> =
  [T] extends [unknown] ? T[] : never;

type Result = ToArray<string | number>;
// (string | number)[]

5. Mapped types are type-level iteration

type Flags<T> = {
  [K in keyof T]: boolean;
};

type Features = {
  search: string;
  analytics: number;
};

type FeatureFlags = Flags<Features>;
// { search: boolean; analytics: boolean }

Combine keyof, indexed access and mapped types and you can build types that mirror runtime objects while preserving relationships between their keys and values.

6. Key remapping

type Getters<T> = {
  [K in keyof T as
    `get${Capitalize<string & K>}`]: () => T[K]
};

type Person = {
  name: string;
  age: number;
};

type PersonGetters = Getters<Person>;

/*
{
  getName: () => string;
  getAge: () => number;
}
*/

Template literal types turn property names into another dimension of type-level computation.

7. Generic inference is about relationships

function mapValue<T, U>(
  value: T,
  map: (value: T) => U
): U {
  return map(value);
}

const result =
  mapValue("hello", value => value.length);
// number

The compiler infers T from the value, uses it to type the callback, then infers U from the callback result. Good generic APIs expose relationships the compiler can follow.

8. Variance explains tricky callback errors

Variance describes what happens when related types are substituted into a generic type. Functions are the classic example: parameter types generally behave contravariantly.

type Handler<T> = (value: T) => void;

declare const animalHandler: Handler<Animal>;
declare const dogHandler: Handler<Dog>;

dogHandler = animalHandler; // safe
// animalHandler = dogHandler; // unsafe

Understanding variance makes errors involving callbacks, event handlers and generic libraries much less mysterious.

9. never is the empty set

If types are sets, never is the empty set. That makes it ideal for exhaustive checks.

function assertNever(value: never): never {
  throw new Error("Unexpected value");
}

type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; size: number };

function area(shape: Shape) {
  switch (shape.kind) {
    case "circle": return Math.PI * shape.radius ** 2;
    case "square": return shape.size ** 2;
    default: return assertNever(shape);
  }
}

Add another variant and the compiler identifies the supposedly unreachable branch.

10. Branded types create domain distinctions

type UserId =
  string & { readonly __brand: "UserId" };

type OrderId =
  string & { readonly __brand: "OrderId" };

function getOrder(id: OrderId) {
  // ...
}

Structural typing normally makes strings interchangeable. A brand creates a compile-time distinction without changing the runtime representation.

11. Derive types from a source of truth

const routes = {
  users: "/api/users",
  orders: "/api/orders",
} as const;

type Route =
  typeof routes[keyof typeof routes];
// "/api/users" | "/api/orders"

as const prevents widening, typeof captures the value's type, and indexed access extracts the union. This pattern is useful for routes, event maps, command registries and configuration.

12. Type-level programming has real limits

Important: TypeScript types disappear at runtime. A type assertion does not validate external data.

TypeScript deliberately makes compromises for JavaScript compatibility, usability and compiler performance. An API response typed as User is not automatically a User. Network data still needs runtime validation.

13. A practical experiment: type-safe event maps

type Events = {
  userCreated: { id: string; email: string };
  orderPaid: { orderId: string; amount: number };
  userDeleted: { id: string };
};

function on<K extends keyof Events>(
  event: K,
  handler: (payload: Events[K]) => void
) {
  // register handler
}

on("orderPaid", event => {
  event.amount;  // number
  event.orderId; // string
});

Now deliberately introduce errors: use the wrong event name, access a property belonging to another event, or change a payload. The interesting part is seeing how the key-to-payload relationship survives through the generic API.

The bigger idea

Advanced TypeScript is less about memorising clever syntax and more about expressing relationships. Conditional types branch. infer extracts structure. Mapped types transform structure. Distributive types operate over union members. Variance describes safe substitution. never represents impossibility.

Once those primitives click, many “magic” library types stop looking magical. They become small programs executed by the compiler.
